# Section 2: Run Example

This section walks you through the core ESP-IDF development loop in Visual Studio Code: opening an example project, configuring it, and then building, flashing, and monitoring it on your ESP32 board.

:::info

Before starting, make sure you have completed environment setup, including installing ESP-IDF, Visual Studio Code, and the ESP-IDF extension.

See: [**Section 1: Set Up Environment**](./esp-idf-installation)

:::

:::tip

The steps below apply to any ESP32-series board. Screenshots and pin numbers in this tutorial reference Tarangify boards such as the **T-CORE-S3-24V** and **T-CORE-S3-BAT**. If you are using a different board, adjust GPIO numbers and hardware-specific settings accordingly.

:::

By the end of this section, you will have flashed and run both the **Hello World** example and the **Blink** example, and you will understand the basic structure of an ESP-IDF project.

---

## 1. The Hello World Example

The **Hello World** example is the simplest possible ESP-IDF project. It prints `Hello, world!` to the serial monitor and is a good first check that your toolchain, board, and serial connection are all working correctly.

### 1.1 Create the Project from a Template

1. Open Visual Studio Code and click the ESP-IDF extension icon in the sidebar.
2. Under the extension's project-creation options, choose **New Project Wizard**.
3. Select the ESP-IDF version you want the project to use.
4. From the list of templates, choose **ESP-IDF Examples**, then locate **hello_world** under the **get-started** category.
5. Confirm creation using that template.
6. Choose a project name and a save location, then create the project.

:::danger

The project path must not contain spaces, non-ASCII characters, or other special characters. Paths that violate this can cause the build system to fail.

:::

7. Once the extension finishes copying the template files, open the newly created project.

### 1.2 Understanding the Project Structure

A freshly created `hello_world` project has a small, predictable layout:

```text
hello_world/
├── CMakeLists.txt
├── pytest_hello_world.py
├── main
│   ├── CMakeLists.txt
│   └── hello_world_main.c
└── README.md
```

- **`main/`** — the project's default component. This is where your application code lives.
  - `hello_world_main.c` — the C source file containing `app_main()`, the entry point ESP-IDF calls when the device boots.
  - `CMakeLists.txt` — the component-level build script, listing source files and include paths for this component.
- **`CMakeLists.txt`** (project root) — the project-level build script. It declares the project (for example `project(hello_world)`) and pulls in subdirectories such as `main/`.

Two more items appear automatically once you build the project:

- **`build/`** — generated by the build system. Contains object files, intermediate build artifacts, and the final firmware binaries.
- **`sdkconfig`** — the resolved project configuration, written whenever you change settings through `menuconfig` or the SDK Configuration editor (Wi-Fi settings, log levels, and so on). Avoid editing this file by hand, since it can get out of sync with your configuration sources.

### 1.3 Configure Target, Port, and Flash Method

Before building, set up how the extension will talk to your board. These controls live in the ESP-IDF toolbar at the bottom of the VS Code window (see [Section 1, "VS Code ESP-IDF Interface"](./esp-idf-installation#4-vs-code-esp-idf-interface) for a reference).

1. **Flash Method** — choose the interface used to program the board (typically UART for most boards).
2. **Select Port** — connect your board over USB, then pick the matching serial port from the list.
   - If you're not sure which port is yours, unplug the board and see which entry disappears, then plug it back in.
   - If no new port appears, some boards need to be put into download mode manually: hold the **BOOT** button, plug in the USB cable, then release **BOOT**.
3. **Set Target** — select the chip that matches your board (for example `esp32s3` for ESP32-S3-based Tarangify boards).

:::info

The first time you set a target, ESP-IDF may need to download the matching toolchain and libraries. This can take a few minutes depending on your connection.

:::

### 1.4 Build

Click the **Build** icon in the toolbar to compile the project.

Equivalent command:

```bash
idf.py build
```

A successful build produces:

- An application ELF file (used for debugging)
- A flashable firmware binary (`.bin`)
- A bootloader binary
- A partition table binary

### 1.5 Flash

Click the **Flash** icon to write the compiled firmware to your board.

Equivalent command:

```bash
idf.py flash
```

Behind the scenes, the extension uses `esptool` to communicate with the board's bootloader and transfer the firmware. Progress is shown in the integrated terminal.

### 1.6 Monitor

Click the **Monitor** icon to open the serial monitor and view your board's runtime output.

Equivalent command:

```bash
idf.py monitor
```

Once connected, you should see the board boot and print `Hello, world!` to the terminal.

Exit the monitor at any time with:

```text
Ctrl + ]
```

### 1.7 Build, Flash, and Monitor Together

Rather than running each step separately, you can click the combined **Build, Flash and Monitor** icon to do all three in sequence.

Equivalent command:

```bash
idf.py build flash monitor
```

## 2. The Blink Example

Next, try the classic **Blink** example, which flashes an LED on your board at a fixed interval. This example also introduces project-specific configuration options, which is useful once you start customizing examples for your own hardware.

Blink supports both simple GPIO-driven LEDs and addressable LEDs (such as WS2812-style RGB LEDs) driven over RMT or SPI.

### 2.1 Open the Blink Project

Follow the same steps as in [1.1](#11-create-the-project-from-a-template), but choose **blink** from the **get-started** category instead of `hello_world`.

### 2.2 Project Structure and sdkconfig Defaults

The Blink example has a similar layout to Hello World, plus a set of default configuration files for different target chips:

```text
blink/
├── CMakeLists.txt
├── main
│   ├── blink_example_main.c
│   ├── CMakeLists.txt
│   ├── idf_component.yml
│   └── Kconfig.projbuild
├── pytest_blink.py
├── README.md
├── sdkconfig.defaults
├── sdkconfig.defaults.esp32
├── sdkconfig.defaults.esp32c3
├── sdkconfig.defaults.esp32c5
├── sdkconfig.defaults.esp32c6
├── sdkconfig.defaults.esp32c61
├── sdkconfig.defaults.esp32h2
├── sdkconfig.defaults.esp32p4
├── sdkconfig.defaults.esp32s2
└── sdkconfig.defaults.esp32s3
```

During a build, ESP-IDF applies the generic `sdkconfig.defaults` file first, then layers on a chip-specific file such as `sdkconfig.defaults.esp32s3` based on your selected target. Where the same setting appears in both files, the chip-specific value wins.

The `main/Kconfig.projbuild` file defines project-specific configuration options — such as the LED type and GPIO pin — that show up in `menuconfig` and get written into `sdkconfig`.

### 2.3 Confirm Target, Port, and Flash Method

Double-check the target chip, serial port, and flash method as described in [1.3](#13-configure-target-port-and-flash-method) before continuing.

### 2.4 Configure the LED Pin

You can change Blink's LED settings either through the graphical SDK Configuration editor or the classic terminal-based `menuconfig`.

**Using the SDK Configuration editor:**

1. Open the SDK Configuration editor from the toolbar. It offers a more visual alternative to the terminal-based configuration tool.
2. Adjust the relevant settings:
   - **Blink LED type** — `GPIO` for a standard LED, or `LED strip` for an addressable LED such as WS2812.
   - **Blink GPIO number** — the GPIO pin connected to the LED.
   - **Blink period in ms** — how often the LED toggles.
3. Save your changes.

**Using terminal-based menuconfig:**

1. Run:

   ```bash
   idf.py menuconfig
   ```

2. Navigate to **Example Configuration** using the arrow keys, and press Enter to expand it.
3. Set the same three options — LED type, GPIO number, and blink period.
4. Press `S` to save, then `Q` to quit.

:::info

Check your Tarangify board's documentation for the correct LED type and GPIO number — this varies by board model.

:::

### 2.5 Build, Flash, and Monitor

Use the combined **Build, Flash and Monitor** icon (or `idf.py build flash monitor`) to compile, upload, and watch the output in one step.

Once flashing finishes, the onboard LED should start blinking, and the serial monitor will show the example's log output.
