# SPI Communication

SPI (Serial Peripheral Interface) is a high-speed synchronous communication protocol widely used in embedded systems. It enables fast data exchange between a microcontroller and peripherals such as displays, SD cards, sensors, and external memory devices. SPI is generally faster than both UART and I2C, making it suitable for applications that require high data transfer rates. :contentReference[oaicite:0]{index=0}

In this tutorial, you will learn:

- What SPI is
- How SPI communication works
- SPI signal lines
- Master and Peripheral devices
- Using SPI on ESP32
- Communicating with an SD Card
- Driving SPI Displays
- Common SPI functions

---

# What is SPI?

SPI stands for:

```text
Serial Peripheral Interface
```

SPI is a synchronous communication protocol, meaning that data transfers are controlled by a clock signal generated by the controller (master) device. :contentReference[oaicite:1]{index=1}

Unlike UART, SPI does not require a baud rate agreement, and unlike I2C, it does not use addressing.

---

# SPI Signal Lines

A standard SPI connection uses four signals:

| Signal | Description |
|----------|----------|
| SCK | Serial Clock |
| MOSI | Master Out Slave In |
| MISO | Master In Slave Out |
| CS | Chip Select |

---

## SCK (Clock)

The controller generates the clock signal.

```text
SCK
```

All SPI communication is synchronized using this clock.

---

## MOSI

Data sent from the controller to the peripheral.

```text
MOSI
```

Example:

```text
ESP32 → OLED Display
ESP32 → SD Card
```

---

## MISO

Data sent from the peripheral back to the controller.

```text
MISO
```

Example:

```text
SD Card → ESP32
Sensor → ESP32
```

---

## CS (Chip Select)

Used to select a specific peripheral.

```text
CS
```

When CS is LOW, the selected peripheral becomes active.

---

# SPI Bus Structure

```text
           ESP32
      ┌────────────┐
 SCK ─┤            ├──────── Display
MOSI ─┤            ├──────── SD Card
MISO ─┤            ├──────── Sensor
      └────────────┘
         │    │
        CS1  CS2
```

All devices share SCK, MOSI, and MISO.

Each device requires its own CS pin. :contentReference[oaicite:2]{index=2}

# SPI Features

SPI provides:

- High-Speed Communication
- Full Duplex Data Transfer
- Simple Protocol Structure
- Low Communication Overhead
- Support for Multiple Devices

SPI communication can reach several MHz depending on hardware capabilities. :contentReference[oaicite:3]{index=3}

# Master and Peripheral

SPI follows a controller-peripheral architecture.

### Controller (Master)

The controller:

- Generates Clock Signal
- Initiates Communication
- Selects Devices

Example:

```text
ESP32
```

### Peripheral (Slave)

The peripheral:

- Responds to Requests
- Sends or Receives Data

Examples:

```text
OLED Display
SD Card
Flash Memory
Sensor Module
```

# SPI on ESP32

ESP32 includes dedicated hardware SPI controllers.

The Arduino framework provides access through:

```cpp
#include <SPI.h>
```

Create the SPI bus:

```cpp
SPI.begin();
```

The ESP32 allows flexible pin mapping for SPI communication. :contentReference[oaicite:4]{index=4}

# Example 2: Reading an SD Card

SPI is commonly used for SD card modules.

### Connections

| SD Card | ESP32 |
|---------|---------|
| SCK | SCK |
| MOSI | MOSI |
| MISO | MISO |
| CS | GPIO10 |
| VCC | 3.3V |
| GND | GND |

---

### Code

```cpp
#include <SPI.h>
#include <SD.h>

#define SD_CS 10

void setup()
{
  Serial.begin(115200);

  if(SD.begin(SD_CS))
  {
    Serial.println("SD Card Detected");
  }
  else
  {
    Serial.println("SD Card Not Found");
  }
}

void loop()
{

}
```

# SPI Data Transfer

Sending one byte:

```cpp
SPI.transfer(0x55);
```

Sending multiple bytes:

```cpp
SPI.transfer(buffer, length);
```

Receiving data:

```cpp
byte data =
SPI.transfer(0x00);
```

The same transfer operation can send and receive data simultaneously because SPI is full duplex. :contentReference[oaicite:6]{index=6}

---

# Common SPI Functions

## Initialize SPI

```cpp
SPI.begin();
```

## Start Communication

```cpp
SPI.beginTransaction(
SPISettings(
1000000,
MSBFIRST,
SPI_MODE0));
```

## Send Data

```cpp
SPI.transfer(data);
```

## End Communication

```cpp
SPI.endTransaction();
```

# SPI vs I2C vs UART

| Feature | SPI | I2C | UART |
|----------|----------|----------|----------|
| Speed | High | Medium | Medium |
| Wires | 4+ | 2 | 2 |
| Full Duplex | Yes | No | Yes |
| Addressing | No | Yes | No |
| Multiple Devices | Yes | Yes | Limited |
